## 一、语义定义（新口径）

| 事项 | V4.3（旧，收盘成交） | **V4.4（新，开盘成交）** |
|---|---|---|
| 成交时点 | T 收盘信号 → **T+1 收盘**成交 | T 收盘信号 → **T+1 开盘**成交 |
| 首日收益 | T+2 起 close/close | **成交当日** open→close：`close(T+1)/open(T+1) − 1` |
| 后续日收益 | close/close | close/close（不变） |
| 卖出/换仓 | T+1 收盘价 | T+1 开盘价（换仓仍双边成本） |
| 止损执行 | T 收盘判定 → T+1 收盘卖 | T 收盘判定 → **T+1 开盘卖**（止损信号判定仍是收盘口径） |
| 信号与因子 | 全部 T 日收盘可得，无未来数据 | **不变**（F1–F8 公式零改动；尾盘 24bar 重排在 T 15:00 定榜，T+1 开盘恰好是其后的第一个可成交价，因果性更紧） |

每条收益数字的五要素标注中"成交口径"一栏自此区分收盘/开盘。

## 二、引擎改动设计（resonance 层，禁止新建引擎文件）

1. `V3Params` 新增字段 `exec_price: str = "close"`（取值 `"close" |
   "open"`；**默认收盘**，保证旧口径与历史锚点复现零迁移成本；V4.4
   生产配置显式设 `"open"`）。
2. `V3Backtester.__init__` 新增可选参数 `open_all: pd.DataFrame | None`；
   `exec_price="open"` 时必须提供（开盘价宽表，`ops/backtest_v3.py:
   load_wide` 相应增加 open 列导出——daily parquet 本就含 open 字段）。
3. `exec_pending` 的成交价取 `open_at(i, code)`；当日计收益分支在
   `i == exec_i` 时乘 `close(i)/open(i)`（持仓），其后日 close/close。
   空仓日、成本乘子（单边 bp、换仓双边）、几何复利结构不变。
4. OOS runner（`ops/signal_daily.py`）FROZEN 增 `exec_price="open"` 并
   传入开盘宽表；控制台指令文案改为"T 信号 → T+1 开盘执行"。
