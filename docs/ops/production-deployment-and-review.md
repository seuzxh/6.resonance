# 生产并行部署与复盘方案

生效日期：2026-10-05。本方案响应本轮用户指令：生产阶段并行运行 D3（三锚动选）与 D2（双锚动选）。本仓库仍然没有实盘下单接口；“生产”指纸面生产账户、信号发布、审计与复盘链路。

## 一、结论与边界

生产链路并行运行两条账户：D3 使用深证成指、国证2000、科创50三锚动选；D2 使用深证成指、中证1000双锚动选。两轨共用 V4.4 冻结参数：信号日 T（当日）收盘计算，T+1（下一交易日）开盘执行，单边成本 10 个基点（0.1%）。

D2 是生产并行纸面轨，不改变原 A9（九池对照）、B13（历史十三池名义对照）、C1（深证成指单锚）、D3（三锚主轨）四条样本外评价轨的预注册判据。切换、降级或停止任何一轨都必须由人工裁决；审计智能体只能提出建议。

概念指数不可直接交易，成本是统一压力假设。概念目录为存活快照回填，存在幸存者偏差。2026-09-29 以前的净值曲线是历史拼接展示；2026-09-29 起是官方样本外空仓起步账单。

## 二、并行方案

| 轨道 | 锚池 | 角色 | 参数 |
|---|---|---|---|
| D3 | 深证成指、国证2000、科创50 | 现行生产主轨 | V4.4 冻结参数 |
| D2 | 深证成指、中证1000 | 生产并行纸面轨 | 与 D3 完全相同 |
| C1（深证成指单锚） | 单一固定锚 | 正式评价轨，账单落盘、不进站点 | 与 D3 完全相同 |
| G2（国证2000单锚）、K5（科创50单锚） | 单一固定锚 | 2026-10-08 起撤下站点展示，账单照常落盘 | 与 D3 完全相同 |

两轨每日独立选择当日锚、独立维护持仓、独立计费与止损。D2 不继承 D3 的入场价、持仓年龄或净值。站点并列展示两轨，不用加权净值替代两轨。

## 三、展示与净值口径

生产总览页读取 `nav.json`：

1. 净值曲线从 2026-01-01 起展示，至最新官方信号日。
2. 2026-09-29 前为历史重放；2026-09-29 起为官方样本外账单，并按历史段末值缩放拼接。
3. 悬停净值曲线可见当日概念指数持仓与买卖事件。
4. 生产总览页显示当前持仓、仓位、T+1 开盘滞后指令、当日锚、闸门、半衰期档位、锚池收益排序和最终候选榜。
5. 仓位只有 0% 或 100%：空仓为 0%，持有一个概念指数为 100%。当前引擎没有部分仓位。

最终候选榜同时给出日线分与分钟重排分。若分钟分缺失，页面显示“降级”；降级计数进入审计。

## 四、数据更新与加工流程

```mermaid
flow TD
    A[15:10 定时运行器] -->|补日线| B[daily_bars.parquet]
    B -->|前五名预选+当日锚| C[尾盘5分钟自愈]
    C --> D[生产缓存]
    D -->|D3/D2独立重放| E[净值、交易、快照]
    E -->|发布| F[生产总览站点]
    F -->|00:30审计| G[复盘报告与优化队列]
```

### 1. 日线更新

1. `ops/signal_daily.py` 在 15:05 后允许运行，定时器安排在 15:10。
2. 脚本按活跃代码的最小末日补采日线，每批 10 个代码，失败重试三次。
3. 写回使用 `keep="last"`，收盘真值覆盖盘中污染行。
4. 当日信号只用已收盘日线，不允许用盘中价格替代。

### 2. 分钟数据更新

1. 运行器先算日线候选，再按“当日 Top5（前五名预选）加当日锚”补采尾盘 5 分钟 K线。
2. 请求从 12:00 开始，只取下午盘，目标为 24 根 K线。
3. 新鲜度按“代码加当日是否有 K线”判断；跨日旧 K线不算覆盖。
4. 无高频覆盖代码进入 `oos_nocover.json`，后续不再重复请求。
5. 领先指数窗口缺失时回退日线排序；个别概念缺失时剔除；可评分概念少于两个时回退日线排序。所有降级必须计数。

### 3. 盘中请求方案

官方信号仍只在收盘后生成。盘中只做监控，不生成正式指令：

| 时段 | 动作 | 输出 |
|---|---|---|
| 09:35–14:45 | 每 5 分钟请求当前持仓与锚池最新 5 分钟 K线 | 仅状态页，不写生产缓存 |
| 14:50–15:00 | 请求昨日 Top5（前五名预选）与当日锚，生成临时分钟重排观察 | `outputs/production/intraday_latest.json` |
| 15:05 后 | 运行官方日线更新与完整重放 | `outputs/oos/` 官方产物 |

盘中产物标记为“临时观察”。它不进入 `daily_bars.parquet`、`minute5_bars.parquet`、净值或交易文件。若临时观察与收盘官方信号不同，以收盘官方信号为准。

### 4. 概念目录

概念目录不每日自动变更。每月人工核对一次目录差异，先形成变更清单，再决定是否新开版本。这样避免标的全集在评价期内无声变化。

## 五、部署方案

### 1. 部署前提

- 项目路径：`/home/zxh/projects/6.resonance`。
- Python 环境：conda `resonance`。
- iFinD 凭证可从本机全局源读取。
- `data/cache/` 是唯一生产行情副本，必须另做备份。
- Git 工作区必须干净；审计服务默认强制检查这一条。

### 2. 部署步骤

```bash
cd /home/zxh/projects/6.resonance
conda run -n resonance python -m pytest
conda run -n resonance python ops/signal_daily.py --date <已收盘日期> --no-publish
conda run -n resonance python ops/audit_agent.py --date <审计日期> --dry-run
conda run -n resonance python ops/publish_site.py --dry-run
cd site && npm run docs:build && cd ..
```

通过后安装用户级定时器：

```bash
mkdir -p ~/.config/systemd/user
cp ops/systemd/resonance-signal.service ops/systemd/resonance-signal.timer \
   ops/systemd/resonance-audit.service ops/systemd/resonance-audit.timer \
   ~/.config/systemd/user/
systemctl --user daemon-reload
systemctl --user enable --now resonance-signal.timer resonance-audit.timer
loginctl enable-linger "$USER"
```

核对命令：

```bash
systemctl --user list-timers resonance-signal.timer resonance-audit.timer
journalctl --user -u resonance-signal.service -n 100 --no-pager
journalctl --user -u resonance-audit.service -n 100 --no-pager
```

### 3. 故障处理

| 故障 | 处理 | 禁止事项 |
|---|---|---|
| 日线部分失败 | 15:05 后重跑运行器 | 不用盘中数据补当日 |
| 分钟缺口 | 运行器自愈补采；仍缺失按预注册降级 | 不手工改排名 |
| 发布失败 | 账户数据已落盘，修复后运行 `ops/publish_site.py` | 不回删官方账单 |
| 审计失败 | 查看 `audit_latest.json` 与日志 | 不跳过当日审计 |
| Git 推送失败 | 本地结果保留，网络恢复后推送 | 不手改 `site/public/data/` |

## 六、凌晨审计智能体

`ops/audit_agent.py` 每日 00:30 运行。它只读数据与账单，不触网、不改参、不重算账户。

审计内容：

1. D3 与 D2 官方净值文件是否存在。
2. 日线末日、两轨净值末日、生产快照信号日是否一致。
3. 单日绝对收益是否超过 20%。
4. 持仓与 0% 或 100% 仓位是否相容。
5. 5 分钟数据是否滞后。
6. 分钟重排降级计数。
7. 两轨展示收益差是否超过 10 个百分点。

输出：

- `outputs/production/audit_latest.json`
- `outputs/production/audit_<日期>.md`
- `site/public/data/audit.json`
- 生产总览页的审计状态与优化队列。

## 七、复盘方案

### 1. 每日复盘

每日审计先核对数据与账单一致性，再列当日锚、持仓、滞后指令和降级。若状态不是 `ok`，先修数据与运行链路。

### 2. 每周复盘

每周人工复核：

1. D3 与 D2 的锚选择差异。
2. 两轨概念持仓重叠天数。
3. 止损、空榜退出与换仓后的修复形态。
4. 分钟降级是否集中在特定代码或日期。
5. 优化队列中是否出现需要新预注册的机制课题。

### 3. 每月复盘

每月执行同数据重放，要求净值与交易文件逐位一致。每月核对概念目录、备份可用性和站点发布链路。

### 4. 人工裁决

两轨并行达到至少 60 个信号日后，才可进入裁决。裁决比较同窗、单边 10 个基点下的累计收益、最大回撤和夏普；至少两项占优者胜出。若累计收益差小于 5 个百分点且滚动 20 日相对优势方向翻转少于三次，维持 D3。裁决前任何短期表现差异只进入观察记录。

## 八、2026-10-05 核验结果

在 2026-01-01 至 2026-09-30、单边 10 个基点、历史拼接加官方样本外账单的展示口径下，D3 三锚动选累计收益为 +59.71%，优于 D2 双锚动选的 +32.69%，差额为 +27.02 个百分点。同窗口下，D3 最大回撤为 -12.82%，D2 最大回撤为 -17.98%。2026-09-29 前属于历史展示段，之后属于官方样本外空仓起步段。

截至 2026-09-30，D3 与 D2 均为空仓，仓位为 0%。D3 当日锚为国证2000，闸门未通过；D2 当日锚为中证1000，闸门未通过。两轨最终候选榜为空，均无滞后指令。

凌晨审计智能体试运行结果为告警：5 分钟数据末日为 2026-09-23，落后日线末日 7 个自然日。因两轨闸门未通过，本次账户没有分钟降级事件。优化队列要求先补齐按需 5 分钟数据，不改冻结参数。
